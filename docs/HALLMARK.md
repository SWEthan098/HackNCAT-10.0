# Hallmark integration

Repository: https://github.com/Nutlope/hallmark (MIT, v2.0.0, commit `04977e1`, inspected 2026-11-13).

## What Hallmark is (and is not)

Hallmark is a **design skill for coding agents** (Claude Code, Codex, Cursor, OpenCode), not a
component library. It ships rules (the "Floor", reflex and finish gates), 50 visual themes,
scaffolding scripts and a linter (`sloplint`) that catches UI patterns that read as machine-made.
It has **no npm package and no navigation-card component** to install. Its repository also holds a
marketing site and eval harness that are not meant to be copied into an app.

So the integration is three real things, not copied code:

1. **The skill is installed** for Claude Code at `~/.claude/skills/hallmark`, using the repo's own
   installer (`node skills/hallmark/scripts/install.mjs --claude`), which validated all themes and
   references first. Only the `skills/hallmark` folder was downloaded (sparse checkout). The other
   skills in `~/.claude/skills` were left alone.
2. **The design tokens were generated by Hallmark**:
   `node ~/.claude/skills/hallmark/scripts/theme.mjs scaffold cobalt --scope app` wrote
   `web/src/app/tokens.css` (the Cobalt theme palette, type faces, radii, shadows, spacing and motion
   scale) and `web/src/app/base.css` (focus rings, `overflow-x: clip`, reduced-motion fallback). They
   sit beside `globals.css`, which carries the Hallmark stamp and maps the tokens to Tailwind
   utilities. `base.css` is wrapped in `@layer base` so Tailwind utilities can override it.
3. **The UI is linted by Hallmark**: `sloplint` checks the whole frontend.

## How the components follow it

The navigation cards and the rest of `web/src/components/ui` were written for this app to Hallmark's
app-screen rules (`references/flow.md` § App screens and `references/interaction-and-states.md`):

- `NavCard`: the whole card is one `<Link>` to a real route (or an external link marked as opening a
  new tab). Hover is one signal (1px lift and a border step, hover-capable devices only), press sinks
  1px, focus ring appears instantly, chevron in its own slot (never glued to text), icon `aria-hidden`.
  It has no card inside a card, no gradient, no emoji icons and no invented metrics.
- Inputs never change border width between states; an outline is reserved at rest; labels sit
  above fields; the error replaces the helper line and is tied with `aria-describedby`.
- Buttons are Cobalt "keycaps" with eight states: default, hover, focus, active, disabled, loading,
  error, success.
- Every data region has loading, empty, error and full states.
- Labels and table heads use sentence case in the body face, never tracked capitals.
- Motion uses `transform`/`opacity`/colours only, with a reduced-motion fallback.

## Checking a page

```bash
cd web
node ~/.claude/skills/hallmark/scripts/sloplint.mjs src --genre modern-minimal --scope app
```

Result on 2026-11-13: `sloplint: clean. 0 FAIL, 0 REFLEX, 0 WARN across 31 file(s).` The browser
render checks (`--render`) need `npm i -g puppeteer-core` and Chrome; they have not been run. Pages
were checked visually with Playwright screenshots at 1280x800 and 390x844.

## Using it during the hackathon

- New screen or landing page: in Claude Code, `/hallmark <what to build>`. It will ask about
  material, audience, the action, and tone, then build to the same system.
- Audit an existing page: `/hallmark audit web/src/app/<page>`.
- Keep using the existing tokens: Hallmark reads `tokens.css` and the stamp in `globals.css` during
  pre-flight, so new pages stay in the Cobalt system unless you ask for a redesign.
